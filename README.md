# owlcha-ledger

ระบบบันทึกรายรับ-รายจ่ายร้าน Owl Cha — Next.js 16 (App Router) บน Vercel
แทนที่ระบบเดิมบน Google Apps Script (เก็บไว้ที่ [docs/legacy/](docs/legacy/) เพื่ออ้างอิงเท่านั้น)

สถาปัตยกรรมและเหตุผลการตัดสินใจทั้งหมด: [docs/ADR-001.md](docs/ADR-001.md)

## Stack

- Next.js 16.2.11 (App Router, Turbopack) / React 19.2 / TypeScript 5.9 `strict`
- Node.js 24.x (`.nvmrc`, `engines`)
- Tailwind CSS 4.3 (build จริง — ไม่ใช้ CDN)
- Auth.js v5 (`next-auth@5.0.0-beta.32` pin ตายตัว — ดู ADR R-9)
- Google Sheets API ผ่าน token ของผู้ใช้ (scope `spreadsheets` — ดู ADR §11.6)
- zod / sweetalert2 / html2canvas-pro (dynamic import) / vitest

## เริ่มพัฒนา

```bash
# ใช้ Node 24 (nvm use หรือติดตั้งจาก nodejs.org)
npm install
cp .env.example .env.local   # เติมค่าจริง — ห้าม commit
npm run dev                  # http://localhost:3000
npm run build
npm test
```

แอปตรวจ environment variables ทั้งหมดตอนเริ่มทำงาน (`instrumentation.ts` → `src/lib/env.ts`)
ขาดคีย์ใดจะล้มทันทีพร้อมบอกชื่อคีย์ — รายชื่อคีย์ทั้งหมดอยู่ใน [.env.example](.env.example)

## รายการมาตรฐานและเครื่องมือเจ้าของร้าน

เมื่อ API ตอบ `403 SHEET_ACCESS` แอปจะออกจากระบบอัตโนมัติ (ล้าง session)
และกลับไปหน้าล็อกอินเพื่อให้เข้าสู่ระบบ Google ใหม่ ทุกหน้าที่เรียก API ใช้กติกาเดียวกัน
การล็อกอินใหม่ไม่เพิ่มสิทธิ์ในไฟล์ชีต ต้องใช้บัญชีที่เจ้าของร้านแชร์ไฟล์ให้แบบ Editor
ข้อผิดพลาดประเภทอื่นยังแสดงและจัดการตามเดิม

- `/settings`: ตั้งชื่อมาตรฐาน ชื่อเรียกอื่น และรายการโปรด รวมถึงรายการประจำ
  ที่กำหนดประเภท ช่องทาง และจำนวนเงินเริ่มต้นได้ (เว้นเงินว่างได้)
- หน้าบันทึกค้นหาทั้งประวัติชื่อและ alias พร้อมคำแนะนำชื่อใกล้เคียง กดลูกศร
  และ Enter เพื่อเลือกได้ ก่อนบันทึกชื่อใหม่ที่คล้ายของเดิมจะถามผู้ใช้ ไม่รวมชื่อเอง
- ชื่อที่ยืนยัน alias แล้วใช้ชื่อมาตรฐานตอนบันทึก และจัดกลุ่มในรายงานเดิมทั้ง 4 หน้า
  รวมถึง export โดยไม่แก้ข้อความในประวัติบนชีต การแก้เครื่องหมายจากรายงาน
  ยังใช้ข้อความต้นฉบับเพื่อหาแถวเป้าหมาย
- หมวดหมู่ใช้ mapping ของชื่อมาตรฐานก่อน ถ้ายังไม่มีใช้ mapping ของ alias
  ที่พบก่อนตามลำดับชีต (รวม `counted=false`) ควรตรวจหมวดก่อนรวม alias
  ที่เคยมีหมวดหรือกติกา counted ต่างกัน
- รายการประจำเติมเฉพาะวันที่ไม่มีข้อมูล หากตั้งเป็นรายการว่างทั้งหมด
  จะเริ่มด้วยแถวว่างหนึ่งแถว ไม่แก้ข้อมูลวันที่บันทึกแล้ว
- `/dashboard`: เงินรับจริง เงินจ่ายจริง สุทธิ หมวดค่าใช้จ่าย และช่องทางรายรับ
  เดือนนี้ถึงวันนี้ เทียบกับช่วงวันเดียวกันของเดือนก่อน (ตัดวันที่เกินเดือนสั้น)
  ยอดขายเต็มไม่เติมค่าประมาณให้รายการที่ไม่มี F หรือ F น้อยกว่าเงินรับจริง
  ส่วนต่าง gross/net ไม่ใช่กำไรบัญชี และอาจรวมค่าธรรมเนียมหรือการปรับปรุงของแพลตฟอร์ม
- `/data-quality`: วันไม่มีข้อมูลถึงวันนี้ ชื่อว่าง ยอดศูนย์ รายการอาจซ้ำ
  ยังไม่จัดหมวด/ประเภท alias ที่รวมแล้ว และยอดเดลิเวอรีเต็มที่ขาด/ผิดปกติ
  ค้นหา กรอง แบ่งหน้า และเปิดวันเป้าหมายด้วย `/?date=YYYY-MM-DD`
  ไม่แก้หรือลบข้อมูลอัตโนมัติ วันไม่มีรายการอาจเป็นวันหยุด
- Draft หน้าบันทึกแยกตามผู้ใช้และวันใน localStorage พร้อมอ่าน key รุ่นเดิม
  ไม่ถือว่า draft คือข้อมูลที่บันทึกลงชีต โหลดวันใหม่ไม่สำเร็จจะไม่เปิดให้บันทึก

การตั้งค่าใช้ร่วมกันทุกอุปกรณ์และทุกบัญชีที่มีสิทธิ์ เก็บ JSON รุ่นที่ตรวจด้วย zod
ใน A2 ของแท็บ **ตั้งค่ารายการ** สร้างแท็บเมื่อบันทึกการตั้งค่าครั้งแรกเท่านั้น
GET ไม่สร้างแท็บและไม่เขียนบัญชีรายวัน ไม่มี env ใหม่
เวอร์ชันตรวจ stale tab และตอบ 409 ให้โหลดใหม่ แต่ Google Sheets ไม่มี compare-and-swap
การบันทึกพร้อมกันจริงยังอาจเป็น last-write-wins เช่น mapping หมวดเดิม
รองรับชื่อมาตรฐาน 100 ชื่อ ชื่อเรียกอื่น 30 ชื่อต่อรายการ และรายการประจำ 100 แถว
ไม่รองรับชื่อ/alias ที่กำกวมซ้ำข้ามรายการ ไม่รีเซ็ตการตั้งค่าเสียหายเป็นค่าเริ่มต้นเงียบ ๆ

### ทดสอบบน localhost

ใช้ VS Code task **Ledger localhost development** หรือ:

```powershell
node .\node_modules\next\dist\bin\next dev --hostname localhost
```

เปิด `http://localhost:3000` และเข้าสู่ระบบ Google ตามปกติ
Google OAuth ต้องอนุญาต callback `http://localhost:3000/api/auth/callback/google`
การตั้งค่าและ API บน localhost ยังใช้ Google Sheet ตาม `.env.local`
จึงไม่ควรบันทึกรายการทดสอบลงชีตจริง

## หมายเหตุด้าน rendering และ performance

- **ทุกหน้าเป็น dynamic render โดยตั้งใจ** — CSP ใช้ nonce ต่อ request (ตั้งใน [proxy.ts](proxy.ts))
  ซึ่ง opt out จาก static generation; ทุกหน้าอยู่หลัง auth จึงเป็น dynamic โดยธรรมชาติอยู่แล้ว
  ไม่ใช่ regression (ADR-001 §11.4)
- **งบประมาณ bundle หน้าแรก (First Load JS): ≤ 170 kB** วัดบนพื้นฐาน dynamic render —
  ตัวเลขจริงหลัง build จะรายงานไว้ที่นี่ทุก milestone
  - M0 (placeholder): _จะอัปเดตหลัง build_
- `html2canvas-pro` โหลดแบบ dynamic import เฉพาะตอนกดบันทึก ไม่อยู่ใน bundle หลัก

## ความปลอดภัย (สรุป)

- ทุก API route ตรวจ session + allowlist เองเสมอ (`src/lib/guard.ts`) — proxy เป็นแค่ชั้นเสริม
- Session: idle 12 ชม. + absolute cap 5 วัน (บังคับทั้ง proxy และ guard — ADR D8)
- CSP: `script-src` ใช้ nonce (ห้าม unsafe-inline), `style-src` ผ่อน unsafe-inline (ADR R-10)
- ไม่มี secret ใดอยู่ในซอร์ส — อ่านจาก env เท่านั้น และห้าม log
